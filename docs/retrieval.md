# 找

听懂器给了 topic 和 keywords，这一步找出最多 8 个候选。

## 两张榜

- **语义榜**：把 topic 向量化，和每条记忆的向量算余弦相似度，取前 12。解决「说法不同、意思一样」。
- **关键词榜**：`content LIKE '%词%'`，任何一个关键词命中即可，按时间倒序取前 8。解决「专有名词、店名、物件名」这种向量容易糊掉的东西。

只查**仍然有效**的记忆（我们的 provenance 表里 `status='active'`；被撤回、被更正的旧记忆不进候选）。

## 按名次融合（RRF）

两张榜的分数不能直接相加（余弦和关键词命中不是一个量纲），所以只看名次：

```js
const fused = new Map();
[vectorIds, keywordIds].forEach(list =>
  list.forEach((id, rank) => fused.set(id, (fused.get(id) || 0) + 1 / (60 + rank))));
const ranked = [...fused.entries()].sort((a, b) => b[1] - a[1]).map(([id]) => id);
```

在两张榜上都靠前的自然排到最前。常数 60 是 RRF 的常用值，不用调。

## 日期窗口

她说了「昨天」，听懂器给出 `{from, to}`。用记忆的**写入时间**筛：

- 窗口 = `from - 1 天` 到 `to + 2 天`。记忆通常当天或之后一两天才被整理写入，所以往后多放两天；时区差一天，往前多放一天。
- 两张榜和图片都只在窗口里找。
- **窗口里一条都没有 → 退回全部记忆。** 比「那几天没有，所以什么都不给」更有用：她记错日子是常事。

```sql
-- created_at 可能是 'YYYY-MM-DD HH:MM:SS' 或 ISO，统一取前 10 位比较
SELECT id FROM memory WHERE substr(replace(created_at,'T',' '),1,10) BETWEEN ? AND ?
```

## 找图

我们给她发过的每张图离线生成一句描述（用便宜的视觉模型，一两句、只写看得见的东西），存在聊天记录那一行上。之后：

- 有关键词时，图片描述也用 `LIKE` 找，最多 4 张。她在找图时，**一个字的关键词也保留**（「猫」就是最好的词）；平时关键词至少两个字。
- 听懂器说 `image:true` → 图片候选**排在最前**；否则排在文字记忆后面。
- 候选文本写成「（9 月 3 日米娅发过的图）一只橘猫趴在窗台上」，挑选器和 AI 都知道这是图。

这一版只按关键词找图描述；如果你有余力，给图片描述也建向量，就能「按意思找图」。

## 不重复

同一条记忆 30 分钟内给过，就不再进候选。她连着聊同一件事时，AI 已经知道了，再塞一遍只会让它复读。

（这是「挑完之后」的冷却。我们没有做更强的永久拉黑：几小时后她重新提起，就应该能再想起来。）
