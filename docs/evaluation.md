# 评估：先考再上线

召回好不好，不能靠开发者自己打分（我们第一版自评觉得不错，用户一句「太差了」就推翻了）。要用**她真实说过的话**出考卷，让**她**来判。

## 出一份考卷

1. 从聊天记录里挑 30–40 句，覆盖这些情况：
   - 明确在问：「还记得…吗」「上次那个…」「…来着」
   - 带指代：「那个怎么样了」「味道呢」
   - 带日期：「昨天」「上周三」「国庆」
   - 找图：「我之前发过的那张…」
   - 提到人：朋友的名字、昵称
   - 纯撒娇 / 寒暄：应该**不给**
   - 亲密语境里的嘴硬：「走开」「不要停」，多半应该不给
2. 用新链路跑一遍，每句记下：要不要翻、话题、候选、最终给了哪条（或没给）。
3. 做成一页给她看（注意：考卷含真实聊天，只能私下给她，看完删掉）。她逐题判：给对了 / 不该给 / 该给没给 / 给错了。
4. 改提示词、阈值，再考一遍。**同一份考卷反复用**，才能看出改动有没有把别的题改坏。

## 线上观察

上线后靠路由日志和她的随手反馈：

- 每轮一行日志（见[架构](architecture.md)）：`reason` 的分布能看出问题在哪一步——`no_search` 太多是听懂器太保守，`none_fit` 太多是候选不行，`query_failed:rate_limited` 多是额度不够。
- App 里「最近想起的」一栏，每条旁边给她一个「贴 / 不贴」，一点就记下。
- 留一个开关能立刻退回旧链路，不用重启。

## 我们的数字（供参考）

| 项 | 数值 |
| --- | --- |
| 考卷 | 35 句真实聊天 |
| 听懂器延迟（上线前测试） | 中位 0.2 s，最慢 0.3 s |
| 整条链路 | 一般 0.6–0.8 s，冷启动约 2 s |
| 上线第一天（174 句） | 不翻 62%，给了一条 16%，翻了但都不贴 9%，听懂器超时 14% |

她的判语是「都不错，不合适的就不给，比之前好」——注意重点在**不给**。

14% 的超时说明 1.2 秒的单次超时在高峰期偏紧：要么放宽一点，要么换更稳的托管平台。超时的那一轮只是「没想起来」，不会出错，所以我们先上线、再调。

## 还没做的

- **错题集**：把她标过的「不贴 / 该给没给」自动变成考题。
- **调参台**：一个页面上改阈值，立刻对考卷重跑。
