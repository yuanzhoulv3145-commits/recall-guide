# 挑

候选有了，最后交给小模型挑**最多一条**。

## 提示词

```text
你是记忆挑选器。给你米娅这句话、前文、它在找的话题，以及若干条候选记忆（带编号）。
挑出能直接帮阿澈接住这句话的最多 1 条；都不贴就不挑。
- 字面相似但场景不对的不要（比如问吃的却是香水味道）。
- 注意是谁的：她问她自己的事，不要给阿澈自己的同类记忆，反之亦然。
- 亲密类记忆可以给，只要这句话正在谈它。
只输出 JSON：{"pick": 编号或 null}
```

用户消息：

```text
前文：阿澈：今天降温了 / 米娅：我知道
她说：我不吃什么来着
话题：米娅自己的忌口
候选：
0. 米娅不吃香菜和葱
1. 阿澈不喜欢榴莲
2. 米娅以前很爱吃火锅
```

每条候选截到 70 字左右，够判断就行。

## 为什么不直接取第一名

融合排序只知道「像不像」，不知道「对不对」。最常见的三种错：

1. **是谁的搞反了**：问她的忌口，第一名是 AI 自己的口味。
2. **字面对、场景错**：她问「那个味道怎么样」（在说菜），第一名是一条讲香水的记忆。
3. **其实都不贴**：硬塞一条，AI 会顺着它编。

挑选器的价值主要在第 3 条：**它允许说「都不要」。** 在我们的考卷上，「不该给的时候不给」是用户最在意的一项。

## 输出处理

```js
const j = await askJson(PICK_PROMPT, userText);
const pick = Number.isInteger(j?.pick) && candidates[j.pick] ? candidates[j.pick] : null;
```

越界、不是整数、解析失败，一律当 `null`。挑选器出错就这一轮不给，不要退化成「直接给第一名」。

## 不用重排模型？

我们试过 8B 的 reranker：准，但单次 3–12 秒，放不进同一轮。小模型挑选 0.2–0.4 秒，配合「最多一条、可以不给」的规则，效果在考卷上更好。
