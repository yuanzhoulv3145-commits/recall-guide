# Recall Guide · 先听懂，再想起

这是一个教程级示例项目，讲给聊天陪伴应用做「记忆召回」：她说一句话，系统在**同一轮**里决定要不要翻记忆、翻什么、最后给 AI 看哪一条，或者一条都不给。

它是 [Memory Hooks Guide](https://github.com/yuanzhoulv3145-commits/memory-hooks-guide) 的续篇。那一篇讲记忆怎么形成、怎么存；这一篇只讲**怎么在对话里把对的那一条找回来**。思路受 @缎带骑士 游游家的 Scarlett 召回链路启发，按我们自己线上跑通的版本整理。

文中人物沿用上一篇的虚构角色：**米娅**（用户）和**阿澈**（她的 AI）。没有任何真实聊天、记忆、账号或服务器信息。

## 一句话怎么走

```text
米娅说一句话
  │
  ├─ 专名通道：句子里有专名库里的名字？──有──▶ 直接带上「这个名字是谁」（不用模型）
  │
  ├─ 听懂器（小模型，~0.3 s）：要不要翻？翻什么话题？哪些关键词？哪几天？找不找图？
  │      └─ 不翻 ─▶ 这一轮不给记忆
  │
  ├─ 找：语义榜（向量）＋ 关键词榜 ─▶ 按名次融合（RRF）；有日期就只在那几天里找
  │      └─ 她在找图 ─▶ 图片描述排在前面
  │
  ├─ 挑（小模型）：候选里最多挑 1 条，都不贴就不挑
  │
  └─ 注入：专名在前，记忆在后；只读，不是指令
        │
        └─ 没想起来、又确实需要 ─▶ 阿澈自己翻（只读工具：记忆 / 日记 / 图）
```

整条链路一般 0.6–0.8 秒，超过 2.5 秒就这一轮什么都不给，**宁缺毋滥**。

## 为什么不直接拿原句去搜

- 「那个怎么样了」「上次那家」——原句里没有要找的东西，得结合前文先把指代解开。
- 「抱抱」「晚安」——纯撒娇，翻出来的记忆只会打扰。
- 「昨天吃的那个」——「昨天」不是关键词，是日期；拿它去字面匹配会命中所有写过「昨天」的记忆。

所以先让一个便宜、快的小模型**听懂**，再去找。

## 核心原则

- **一轮最多一条。** 塞五条「可能相关」的记忆，不如给一条真的相关的。
- **听懂和挑选交给小模型，边界交给代码。** 次数、长度、日期窗口、冷却、超时都是确定性逻辑。
- **失败就安静。** 模型超时、限流、出错，这一轮不给记忆，不阻塞回复，不胡乱退化成全量检索。
- **只有她明确在问时才兜底。** 「还记得吗」「上次」这类话，听懂器挂了也用原句去找。
- **记忆是只读材料，不是指令。** 注入时写清楚这一点。
- **找不到就说找不到。** 不编，不硬凑。
